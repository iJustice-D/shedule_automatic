# Система расписания колледжа

Практический MVP для диссертационного проекта: генерация, редактирование, проверка конфликтов и экспорт расписания колледжа на Python.

Приложение использует:

- реальную учебную нагрузку из `data/Оқу жоспар_ЕТБ-1124.xls`
- реальный учебный процесс из `data/Үрдіс 2025-2026 оқу жылы соңғысы (1).pdf`
- реальный лист недельной нагрузки и закрепления преподавателей из `data/2025-2026 ПРОГРАММИСТТЕР_ИНКАР (1) (2) (1).docx`
- демонстрационные группы, преподавателей, аудитории и предметы

Интерфейс приложения по умолчанию русскоязычный. Для будущего расширения добавлена простая i18n-структура с заготовкой под казахский язык.

- Весь UI переведен на русский язык.
- Добавлена локализация через `app/ui/i18n/`.
- Введены реальные фиксированные пары колледжа:
  - 1 пара: `08:00-09:20`
  - 2 пара: `09:40-11:00`
  - 3 пара: `11:10-12:30`
  - 4 пара: `13:30-14:50`
  - 5 пара: `15:10-16:30`
  - 6 пара: `16:40-18:00`
- Добавлены смены:
  - утренняя: пары `1-3`
  - послеобеденная: пары `4-6`
- Для групп добавлены поля `shift` и `year`.
- Для предметов добавлены `can_be_online` и `default_delivery_mode`.
- Для записей расписания добавлены `delivery_mode`, `shift`, `start_time`, `end_time`.
- Добавлена политика онлайн-занятий по курсу, группе и предмету.
- Онлайн-занятия вынесены в отдельный слой `online_extra`:
  - не занимают обычные пары `1-6`
  - доступны только в среду, четверг и пятницу
  - показываются отдельным блоком в UI и экспортах
- Генератор теперь учитывает:
  - новый нормализатор нагрузки, который переводит weekly workload в единый internal model
  - states закрепления преподавателей: `fixed / candidate_pool / vacancy / multi_teacher / unresolved`
  - подгруппы `A/B` как отдельные schedulable rows
  - teacher no-overlap как главный hard constraint
  - group no-overlap как второй абсолютный hard constraint
  - смену группы и разделение `regular / online`
  - feasibility pre-check перед построением результата
  - subject completeness по каждой нормализованной строке
  - локальный repair после ручных правок без полной регенерации результата
  - явное разделение `жёсткие конфликты / несоставленная нагрузка / проблемы нормализации`
- Генерация переведена в реальный pipeline запуска:
  - создается отдельный `GenerationJob`
  - этапы запуска фиксируются в истории
  - поддерживаются два режима: `одна группа` и `все группы выбранного семестра`
  - один all-groups job строит несколько независимых `per-group` результатов
  - editor по-прежнему открывает только один scoped result за раз
  - результат открывается только для конкретной группы и конкретного семестра
  - редактор и диагностика привязаны к конкретному `result_id`, а не к "последнему глобальному расписанию"
  - внутренняя генерация теперь идет по этапам `normalization -> feasibility -> construction -> repair -> diagnostics`
- В `Учебной нагрузке` появился импорт недельной нагрузки из DOCX, просмотр нормализованных строк, блок вакансий/неразрешённых строк и отчет по балансу преподавателей между семестрами.
- Онлайн-слоты теперь настраиваются в UI как реальные записи с днем и временем, а не только как подписи.
- В редакторе добавлен фильтр преподавателей с вариантом `Все`.
- В режиме просмотра по группе показываются только пары, доступные для смены выбранной группы.
- Конфликты и предложения переведены на русский язык.
- Экспорт в XLSX/PDF/DOCX теперь использует русские заголовки и показывает смену, время пары и формат занятия.
- Добавлены ручные формы для групп, предметов и учебной нагрузки прямо из UI.
- Ручная нагрузка хранится вместе с импортированной, помечается источником и используется генератором наравне с импортом.
- Рабочий режим по умолчанию очищает неактуальные демонстрационные группы и преподавателей из обычных списков UI и API.
- Предметы канонизируются по нормализованному видимому названию: дубликаты объединяются безопасно, а обычные селекторы показывают только уникальные названия.
- Демонстрационные данные больше не подмешиваются автоматически в реальный режим; demo-seed стал отдельным opt-in сценарием.
- На странице конфликтов ИИ-пояснения теперь открываются в читаемом диалоге, а не в коротких всплывающих уведомлениях.
- PDF-экспорт использует встроенный Unicode-шрифт для корректного вывода кириллицы и казахских символов.
- В редакторе ячейки расписания показывают недели, различают чередование недель и реальные пересечения, а карточки занятий стали читаемее.

## Основные бизнес-правила

- Для обычного расписания используются только учебные недели.
- Практика, экзамены, итоговая аттестация и каникулы блокируются.
- Недельная нагрузка из DOCX делится на:
  - обычную
  - факультативную
  - учебную практику
  - производственную практику
  - строки подгрупп
- Система умеет строить расписание сразу для нескольких групп в одном запуске, при этом teacher no-overlap контролируется на уровне всего запуска, а не только внутри одной группы.
- Каждая исходная строка после импорта попадает в одно из состояний:
  - нормализована и может быть составлена
  - нормализована, но требует ручного уточнения преподавателя
  - исключена из обычной сетки как практика/факультатив
  - требует ручной проверки из-за неоднозначности импорта
- Практика и факультативы не принудительно смешиваются с обычной сеткой пар.
- Утренние группы получают занятия только на парах `1-3`.
- Послеобеденные группы получают занятия только на парах `4-6`.
- Онлайн-занятия идут отдельно от обычной сетки, занимают слот у группы и преподавателя, но не требуют аудитории.
- Онлайн-занятия доступны только в среду, четверг и пятницу в отдельных онлайн-слотах.
- Для 2 и 3 курса целевое значение по умолчанию: `3` онлайн-занятия в неделю.
- Для 1 курса онлайн-режим разрешается только для выбранных общих предметов.

### Ручной ввод из UI

- На странице `Группы` доступны действия `Добавить группу`, `Редактировать группу`, `Удалить`.
- По умолчанию в разделе `Группы` показываются только активные группы; архив выводится отдельным переключателем.
- На странице `Предметы` доступны действия `Добавить предмет`, `Редактировать предмет`, `Удалить`.
- Повторяющиеся названия предметов не допускаются: при создании дубликата приложение возвращает ошибку `Предмет с таким названием уже существует`.
- На странице `Учебная нагрузка` доступны действия `Добавить нагрузку`, `Редактировать нагрузку`, `Удалить`.
- Там же доступен импорт недельной нагрузки из DOCX с последующим просмотром нормализованных строк, вакансий и баланса преподавателей.
- Для нагрузки можно вручную указать группу, предмет, семестр, часы, недели, часов в неделю, пар в неделю, тип занятия, формат проведения и примечание.
- Кнопка `Рассчитать` и переключатель `Авторасчёт` пересчитывают недельную нагрузку из общего количества часов и учебных недель.
- На странице `Генератор расписания` каждый запуск теперь создаёт отдельную запись истории генерации со статусом `Ожидает запуска / Выполняется / Завершено / Ошибка`.
- Для all-groups режима история генерации показывает набор `per-group` результатов, которые можно открывать отдельно.
- После завершения можно открыть именно этот результат, а редактор показывает только его данные для выбранной группы и семестра.

### Новое ядро генерации

- Нормализация умеет строить scoped model как для одной группы, так и для набора групп выбранного семестра.
- Если для группы нет `AcademicPeriod`, semester/week resolver использует нормализованное количество учебных недель из weekly workload и синтезирует корректный week scope для генерации.
- Feasibility analysis считает ожидаемую нагрузку, доступную вместимость смены, online-slot capacity и строки без преподавателя по выбранному scope.
- Детализированный planner сначала размещает фиксированные и более жёсткие строки, затем пытается локально доразместить оставшиеся запросы.
- Каждая запись расписания хранит `source_load_key`, поэтому диагностика знает, какая именно исходная нагрузка покрыта, а какая нет.
- При all-groups запуске planner строит одно совместное решение по нескольким группам и только после этого сохраняет отдельные `Schedule` по каждой группе, связанные общим `GenerationJob`.
- Локальная проверка и ручное редактирование учитывают sibling schedules из того же generation job, поэтому конфликт преподавателя между двумя группами не пропускается.
- Editor после ручного редактирования запускает локальный repair только для затронутого scope и затем повторную валидацию.

## ИИ-пояснения

- Приложение полностью работает без API-ключа.
- `DummyExplanationProvider` используется по умолчанию.
- `GeminiExplanationProvider` оставлен как опциональный провайдер пояснений.
- ИИ не валидирует расписание и не принимает решений о корректности.

## Текущие ограничения

- Генерация выполняется синхронно внутри процесса приложения, но оформлена как полноценный pipeline с `GenerationJob`, прогрессом и историей запусков.
- В качестве `GenerationResult` в текущем MVP используется запись `Schedule`; именно её `id` используется как `result_id` для редактора и диагностических страниц.
- Hard-feasibility stage в текущем MVP реализован как deterministic search + local repair внутри Python, а не как внешний CP-SAT solver. Для диссертационного MVP это даёт управляемое и объяснимое поведение, но не гарантирует глобально оптимальное решение для больших наборов групп.
